# Deploying Project Synapse for free

Target architecture, all on permanently-free tiers:

```
  Cloudflare Pages          Render (free web service)         Neon (free Postgres)
  ┌────────────────┐        ┌───────────────────────┐        ┌──────────────────┐
  │ React SPA      │──HTTPS▶│ FastAPI + uvicorn     │──TLS──▶│ documents,       │
  │ (static build) │        │ Docker, sleeps @15min │        │ chunks, users    │
  └────────────────┘        └───────────────────────┘        │ + pgvector       │
                                                             └──────────────────┘
```

Why this split rather than one host: Cloudflare Pages has no commercial-use
restriction (Vercel's Hobby tier does), Render runs the Docker image as-is, and
Neon is the only part that must persist — so it is the only stateful piece.

**Already done:** the Neon project `project-synapse`
(`small-rice-71537854`, ap-southeast-1) exists, has the `vector` extension
(0.8.6) enabled, and both alembic migrations have been applied to it.

## 0. Prerequisites

Accounts on [Neon](https://neon.tech) (done), [Render](https://render.com) and
[Cloudflare](https://dash.cloudflare.com). All three sign up free with GitHub
and need no card.

Push this branch first — both hosts deploy from GitHub:

```bash
git push -u origin fix/boot-deps-and-deploy-readiness
```

## 1. Database (Neon) — already provisioned

Grab the connection string from the Neon console → *Connection Details* →
**Pooled connection**, then rewrite it for SQLAlchemy:

| Change | Why |
|---|---|
| `postgresql://` → `postgresql+psycopg2://` | SQLAlchemy needs the driver named |
| keep the `-pooler` host | Render's free tier opens and drops connections constantly |
| delete `channel_binding=require` | psycopg2 rejects the parameter |
| keep `sslmode=require` | Neon refuses plaintext |

Result:

```
postgresql+psycopg2://USER:PASSWORD@ep-...-pooler.REGION.aws.neon.tech/neondb?sslmode=require
```

Migrations are already applied. To re-run after a schema change:

```bash
cd backend
DATABASE_URL="<the string above>" alembic upgrade head
```

## 2. Backend (Render)

Render dashboard → **New → Blueprint** → select this repo. It reads
`render.yaml` and prompts for the two values not baked into the file:

| Variable | Value |
|---|---|
| `DATABASE_URL` | the rewritten Neon string from step 1 |
| `CORS_ORIGINS` | your Pages URL, e.g. `https://synapse-frontend.pages.dev` |

Everything else is set by the blueprint. **`SECRET_KEY` is generated by
Render** (`generateValue: true`) — do not set it yourself and do not copy the
placeholder from `.env.example`; the app refuses to start with it whenever
`ENVIRONMENT != local`.

Chicken-and-egg on `CORS_ORIGINS`: you will not know the Pages URL until step
3. Put a placeholder in, finish step 3, then come back and correct it — a
wrong value fails every browser request at preflight while `curl` keeps
working, which is a confusing way to lose an afternoon.

Verify:

```bash
curl https://synapse-backend.onrender.com/health
```

Expect `"status": "ok"`, `"vector_store_backend": "pgvector"`, and
`"retrieval_ready": true`. The first request after idle takes ~50s to wake.

### Creating the first user

`ENVIRONMENT=production` means the demo roster is deliberately **not** seeded —
those credentials are published in this repo. Create a real admin against the
Neon database:

```bash
cd backend
DATABASE_URL="<neon string>" python -c "
from app.db.session import SessionLocal
from app.core.security import hash_password, Role
from app.models.user import User
import getpass
email = input('admin email: ')
pw = getpass.getpass('password: ')
with SessionLocal() as db:
    db.add(User(role_id='T6-LEAD', email=email, hashed_password=hash_password(pw),
                role=Role.ADMIN.value, is_active=True))
    db.commit()
print('created')
"
```

`getpass` keeps the password out of your shell history.

## 3. Frontend (Cloudflare Pages)

Dashboard → **Workers & Pages → Create → Pages → Connect to Git**.

| Setting | Value |
|---|---|
| Build command | `npm ci && npm run build` |
| Build output directory | `dist` |
| Root directory | `frontend` |
| Environment variable | `VITE_API_BASE_URL` = `https://synapse-backend.onrender.com/api/v1` |

`VITE_API_BASE_URL` is consumed at **build** time — Vite inlines it into the
bundle. Changing it later requires a fresh deployment, not a restart. Note the
`/api/v1` suffix: the value is the API base, not the host.

Then return to Render and set `CORS_ORIGINS` to the Pages URL.

## 4. End-to-end check

```bash
API=https://synapse-backend.onrender.com/api/v1
TOKEN=$(curl -s -X POST $API/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"YOUR_ADMIN","password":"YOUR_PASSWORD"}' | jq -r .access_token)

curl -s -X POST $API/documents/text -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"title":"Refund Policy","text":"Customers may request a full refund within 30 days of purchase."}'

curl -s -X POST $API/query -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"question":"How long do I have to request a refund?"}' | jq
```

A grounded answer with a citation and `"refused": false` means the whole
pipeline — ingestion, embedding, pgvector retrieval, grounded generation — is
live.

## Troubleshooting

| Symptom | Cause |
|---|---|
| Backend exits immediately, logs mention `SECRET_KEY` | The placeholder is still set with `ENVIRONMENT != local`. Let Render generate it. |
| Every browser request fails, `curl` works | `CORS_ORIGINS` does not exactly match the Pages origin. Scheme and host must match; no trailing slash. |
| Frontend calls `localhost:8000` | `VITE_API_BASE_URL` was missing at build time. Set it and redeploy — it cannot be fixed at runtime. |
| 404 on every API call, path shows `%20` | Trailing space in `VITE_API_BASE_URL`. `client.ts` trims it, but check the dashboard value. |
| Queries all refuse; documents visible in the UI | `stored_chunks > 0` and `indexed_chunks == 0` on `/health`. The vector store lost its contents — confirm `VECTOR_STORE_BACKEND=pgvector`, then re-ingest. |
| `relation "chunk_embeddings" does not exist` | First run creates it automatically; this means the role cannot `CREATE EXTENSION`. Run `CREATE EXTENSION vector;` once as the Neon owner. |
| First request takes ~50s | Render free tier cold start. Expected. |

## Cost and limits

| Service | Free tier | Limit that bites first |
|---|---|---|
| Neon | 0.5 GB storage, scales to zero | Storage, after a lot of documents |
| Render | 750 instance-hours/month | 15-minute idle sleep |
| Cloudflare Pages | Unlimited requests, 500 builds/month | Build count |

No card required for any of them. If cold starts become unacceptable, the
usual next step is an **Oracle Cloud Always Free** VM (4 ARM cores, 24 GB RAM),
which runs the whole `docker-compose.yml` permanently free with no sleeping —
at the cost of managing the box yourself.
